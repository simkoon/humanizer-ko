# humanizer-ko

한국어 글의 번역투, 상투적 표현, 불필요한 강조를 다듬는 Agent Skill입니다. 사실과 글쓴이의 말투는 유지합니다.

[blader/humanizer](https://github.com/blader/humanizer) v3.0.0을 바탕으로 만든 **비공식 한국어 파생 프로젝트**입니다. 영어 규칙의 직역 대신 한국어 피동·명사화·높임·어미·문서 관습에 맞춰 25개 편집 패턴을 작성했습니다.

별도 서버나 API 키는 필요하지 않습니다. 다만 글을 편집하는 AI 에이전트와 그 모델 사용 환경은 필요합니다. 이 저장소 자체는 텍스트를 자동 변환하는 프로그램이 아닙니다.

## v0.2: 최소 수정과 근거 구분

기본은 최소 수정입니다. 좋은 문장은 그대로 두고, 전체 재작성은 명시적으로 요청받을 때만 합니다. 각 패턴에 관찰 연계·편집 원칙·검증 전 가설을 표시했습니다. 연구에서 특징이 관찰된 것과 고쳤을 때 효과가 검증된 것은 다릅니다.

쉼표·명사화·문단 반복의 점검 기준과 예외를 보강했습니다. 문장을 무조건 짧게 만들거나, 어미를 강제로 섞거나, 특정 단어를 금지하지 않습니다. [근거와 한계](references/evidence.md), [변경 이력](CHANGELOG.md)을 참고하세요. **v0.2의 블라인드 품질 비교는 아직 시행하지 않았습니다.**

## 예시

**편집 전**

> 이번 업데이트는 단순한 개선을 넘어 새로운 지평을 여는 변화입니다. 개발팀에 의해 작성되어진 점검표의 경우 검토가 진행되었습니다. 시험 환경에서 평균 응답 시간이 약 120ms에서 90ms로 줄었습니다. 앞으로 더 나은 미래를 만들어 가길 기대합니다.

**편집 후**

> 이번 업데이트에서는 개발팀이 작성한 점검표를 검토했습니다. 시험 환경에서 평균 응답 시간이 약 120ms에서 90ms로 줄었습니다.

위 예시는 편집 기준을 설명하기 위해 작성한 가상 사례입니다. 실제 성능 측정 결과가 아닙니다. 수치, `약`, `시험 환경`, `검토`라는 범위를 유지했습니다.

**고치지 말아야 하는 문장도 있습니다.**

> 이 작업은 삭제가 아니라 보관입니다. 파일은 30일 후에 삭제됩니다.

이 대조는 실제 동작을 구별하므로 유지합니다. `단순히 A가 아니라 B` 형태를 일괄 삭제하지 않습니다.

## 설치

### Claude Code

사용자 스킬 디렉터리에 복제합니다. 기존 경로가 있으면 덮어쓰지 말고 먼저 내용을 확인하세요.

```sh
git clone https://github.com/simkoon/humanizer-ko.git ~/.claude/skills/humanizer-ko
```

Claude Code에서 `/humanizer-ko`로 호출하거나 자연스럽게 편집을 요청합니다. 프로젝트에서만 사용하려면 저장소를 해당 프로젝트의 `.claude/skills/humanizer-ko`에 둡니다. 스킬 탐색·호출 동작은 클라이언트 버전에 따라 달라질 수 있습니다.

### 다른 에이전트 또는 일반 채팅

[SKILL.md](SKILL.md)를 읽게 하고 편집할 원문을 전달합니다. 파일을 읽는 도구가 없는 채팅에서는 SKILL.md 본문과 원문을 각각 구분해 붙여 넣어도 됩니다.

```text
humanizer-ko/SKILL.md의 기준으로 아래 글을 다듬어줘.
용도: 기술 블로그
말투: 원문의 존댓말 유지
출력: 최종본만

<원문>
여기에 편집할 글
</원문>
```

말투 샘플을 별도로 줄 수도 있습니다. 샘플 속 경험이나 사실은 편집 대상에 추가하지 않습니다.

```text
아래 샘플은 말투만 참고해줘. 경험이나 수치는 가져오지 마.
<말투_샘플>...</말투_샘플>
<원문>...</원문>
```

자동 설치 스크립트와 다른 에이전트의 설정 변경은 포함하지 않습니다. 이 저장소를 만드는 과정에서 사용자의 기존 스킬은 교체하지 않았습니다.

## 원본과 다른 점

- 한국어의 `~에 의해`, `~에 있어`, `~에 대한 검토를 진행`, `~것입니다` 등을 맥락에 따라 다룹니다.
- 문장 리듬을 바꾸려고 `합니다/한다/해요`를 섞지 않습니다.
- 한국어 문서에서 자연스러운 생략, 피동, 개조식, 인사말은 유지합니다.
- 개인 경험·감정·출처를 발명해서 개성을 보충하지 않습니다.
- 기본 출력은 최종본만입니다. 요청하면 수정 과정이나 검토 의견을 제공합니다.
- 숫자뿐 아니라 조건·불확실성·역할·시점·인용·코드를 보호합니다.
- 학술·법률·안전 문서에서는 자연스러움보다 의미 보존을 우선합니다.

## 검증

Python 3.10 이상에서 외부 패키지 없이 실행합니다.

```sh
python3 -m unittest discover -s tests -v
```

자동 검사는 패키지 구조, 규칙 수, 필수 안전장치, 예제 데이터와 보호 문자열을 검사합니다. **LLM을 호출하거나 한국어 편집 품질을 자동으로 입증하지 않습니다.** 모델별 동작 검증 방법은 [tests/README.md](tests/README.md)를 참고하세요. 예제의 개선문은 작성한 기준 예시이며, 특정 모델의 실행 결과로 표시하지 않습니다.
